## À arbitrer par le PO

Rangées **provisoirement** selon la règle (« dans le doute, compte »), sauf celles qui décrivent la machine elle-même (raison `machine`), laissées sur l’appareil parce que les envoyer sur le compte n’aurait pas de sens — elles sont listées ici pour que le PO tranche.

| Clé | Rangée aujourd’hui | Recommandation |
|---|---|---|
| `lo-yanum:theme:<…>` | compte | compte — mais ces rôles entrent sans compte (lien d’agriculteur, de gardien) : sans session, la valeur reste dans la copie locale ; elle ne voyage que pour un rôle connecté |
| `lo-yanum:map-last` | compte | compte — sert seulement à répandre une disposition quand on passe en « מסונכרן » ; aucun inconvénient connu à le partager |

| `lo-yanum:map-ratio:<…>` | compte | compte, provisoirement — recommandation : APPAREIL. Un pourcentage choisi sur un écran de 27″ n’a pas de sens sur un iPad (lié à la taille physique de l’écran) |

- **brouillon** : `lo-yanum:zone-draft:<…>`
- **hors ligne** : `lo-yanum:settings-queue`, `lo-yanum`, `lo-yanum-shell-<…>`, `lo-yanum-basemap`

## Écritures indirectes (bibliothèques tierces)

- **supabase-js** : écrivait `lo-yanum:auth` (et, selon le flux, `lo-yanum:auth-code-verifier`, `lo-yanum:auth-user`) DIRECTEMENT dans `localStorage`. Depuis BJ, il reçoit l’adaptateur `authStorage` du registre (`src/data/client.ts`) : une clé qu’il voudrait écrire hors des déclarations est refusée.
- **Service worker** (`public/sw.js`) : Cache Storage `lo-yanum-shell-<version>` (l’application) et `lo-yanum-basemap` (la carte hors ligne). Déclarés ; `bjguard` refuse un cache non déclaré.
- **IndexedDB** : la seule base est `lo-yanum` (`aggregates` + `outbox`), ouverte désormais par `src/storage/idb.ts` (déplacée de `src/data/cache.ts`).
- **MapLibre GL, pmtiles** : aucune écriture dans `localStorage`, `sessionStorage`, IndexedDB ni Cache Storage (recherché dans `node_modules/maplibre-gl/dist/maplibre-gl.js` : 0 occurrence).
- **Cookies** : aucun (`document.cookie` n’apparaît nulle part ; GitHub Pages n’en pose pas).
- **sessionStorage** : un seul usage avant BJ, les sections repliées du formulaire de ferme (`fields.tsx`, `farm-form-*`) ; passé au registre (portée compte, à arbitrer). Plus aucun usage.

## Commentaires et textes qui mentaient

- `lo-yanum:vigil` — he.json settings.vigil.intro disait « הערכים נשמרים במכשיר הזה » alors que la clé voyageait depuis AS4.
- `lo-yanum:map-layers` — MapLegend.tsx (BD 4) disait « synchronisé avec le compte » alors que la clé était dans LOCAL_ONLY_KEYS — relevé et corrigé en BI.
- `lo-yanum:layout-sync` — he.json settings.display.hint disait « ההגדרות האלה נשמרות במכשיר הזה בלבד » — vrai avant BJ, faux depuis ; et « מסונכרן » y désigne les ÉCRANS, pas les appareils.
- `lo-yanum:region-rings` — `regionEdits.ts` et `core/store.ts` disaient « a setting of this device » alors que la clé voyageait avec le compte depuis AH11.2 (sens inverse du mensonge de BI, même défaut : le commentaire ne dit pas où vit la valeur).
- Les commentaires qui disaient « local » pour une clé désormais de compte (rail, bandeau de couverture, « déjà vu » des demandes, destinataire du compte rendu, brouillon d’itinéraire libre, disposition de la carte) portent une note BJ.
